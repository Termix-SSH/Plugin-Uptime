## Overview

Uptime watches websites, ports, hosts and services from Termix and tells you when something goes down. It keeps uptime numbers, response times and a history of every outage, stays quiet during planned work and can publish a public status page. Checks can run from the Termix server or from one of your hosts, so private networks work too.

Read the [docs](https://docs.termix.site/plugins/uptime) to set it up and use it.

<br />

## Features

- Website, TCP port, ping, DNS record and TLS certificate checks
- Termix hosts, Docker containers, systemd units and your own commands
- Check from a host, to reach private networks
- Push monitors for cron jobs and backup scripts
- Uptime numbers, response time charts and an incident history
- Alerts on every channel in the Alerts plugin
- Maintenance windows and public status pages with notes
- Share monitors with users and roles
- Dashboard cards, a panel beside SSH terminals and host page tiles
- Triggers and actions for Automations, Fleets, the CLI and the assistant

## Support

Bugs and ideas for Uptime go in this repo: [report a bug](https://github.com/Termix-SSH/Plugin-Uptime/issues/new?template=bug_report.yml) or [request a feature](https://github.com/Termix-SSH/Plugin-Uptime/issues/new?template=feature_request.yml). Report an issue on the plugin's page in the Plugins tab fills in your versions for you.

Problems with Termix itself (login, hosts, credentials, sharing, sync) go in the [Termix repo](https://github.com/Termix-SSH/Termix/issues/new/choose). Not sure where it goes? Open it there and it will be moved.

Add as much detail as you can, in English if possible. For questions, join the [Discord](https://discord.gg/jVQGdvHDrf) server.
